# Source-based implementation record

Account/diary database structure: additive user/owner bindings, future auth identity structure, notebooks, pages and independent placement rows. Canonical JSON and its normalized projection commit together under a per-page lock. Original fields and access rules remain; no login UI or authenticated member sessions are introduced. Isolated database integrity checks cover owner separation, photo/sticker order, duplicate asset placements, idempotent backfill and transactional rollback. Local migration backs up PostgreSQL, rehearses with rollback and compares existing table fingerprints plus page/placement contents before application. Browser and photo-quality tests remain outside this change.

Page paper controls: diary editing offers six color choices (including the existing photo-adaptive color) and four patterns, with an original-paper reset. The sanitized color/pattern IDs persist per page in notebook JSON as paperStyle. Draft changes preview immediately; publish commits, cancel restores, and failed saves keep the draft. Custom paper uses a separate CSS color variable so asynchronous photo color matching cannot override it. Existing pages retain their original paper by default, and no photo/sticker stacking or database schema changes are required. Source/syntax/build/security checks only; mobile choice controls, save/cancel/reload, page isolation and appearance remain for user verification. No screenshots or browser functional tests were run.

Polaroid stacking: the photo toolbar adds one-step Forward/Backward controls, disabled at the stack boundaries and hidden during rotation. Visible photos have stable array identities and a persisted layerOrder; old pages fall back to their original array order. Rendering assigns bounded z-index ranks only inside the isolated diary photo plane beneath the entire sticker plane. Selecting an obscured photo through the existing photo dropdown now also selects its toolbar. Save/cancel uses the existing diary layout persistence and draft copies. Source/syntax/build/security validation only; overlapping photos, stickers above every photo, boundary controls, selection through the dropdown and save/cancel/reload remain for user interaction testing.

Optional motion onboarding: the owner's diary offers Enable shimmer / Later on first entry, remembers the browser-local preference, and permits later enable/disable or retry after denial. Native sensor permission requests remain directly within the enable button's click handler; a saved app preference is never treated as permission evidence. Editing remains available without permission. Sensor samples are used only for rendering, and startup does not request camera or GPS access. Verification covers source, JavaScript syntax, compilation and secret scans. First-entry allow/later, permission denial/retry, reload, actual phone motion and sensor-unavailable fallback await user testing; no browser interaction or screenshots were run.

Persistent local product catalog: additive SQLite tables store public listings, collection status, price observations, product thumbnails, revision-specific embeddings and private user-confirmed asset links. Product/variant master tables are reserved for verified catalog curation; no automatic identity merge is performed. Existing app rows are fingerprinted and checked on a backup rehearsal, including repeat migration, SQLite integrity and foreign keys. Photo-search UI displays collection dates. Validation excludes live shopping crawls, authenticated Coupang calls, photo-ranking quality and browser interactions, per the user's testing scope.

Direct object editing: selected diary photos/stickers have four corner resize handles and a floating toolbar. Rotate enters a mode without changing the angle: only Apply/Cancel remain in the toolbar, and all four corners become rotation handles with a curved-arrow cursor. Pointer movement rotates around the fixed object center with continuous angle unwrapping; releasing the pointer retains the preview until Apply. Cancel/Escape or selection change restores the angle from before entering rotation mode. Numeric angle input and step buttons are removed; focused handles retain arrow-key support. Unapplied rotation blocks publication. Photo replacement preserves its layout/caption; sticker replacement loads a library asset in a dialog and preserves placement. Delete removes only the page placement. Controls use a separate overlay above photo/sticker planes; bottom sliders are hidden on the diary. Source/syntax/build/security checks only; mouse/touch rotation across the angle boundary, rotated resizing, toolbar positioning, apply/cancel/save/reload and keyboard use await the user's browser testing.

Diary editing correction: all six new stickers now start inside the page; older off-page sticker positions are clamped back into reach. Pointer gestures suppress native drag, release stale capture when editing ends or the window loses focus, and exclude caption controls. Photo selection checks size/dimensions before insertion, blocks publishing while decoding or materializing an asset, and discards cancelled/stale results. Photos remain below the isolated sticker plane; legacy centered polaroids retain their 2D centering transform. Verification is limited to checked source substitutions, JavaScript syntax, Flutter compilation and secret scans. User interaction checks remain: six stickers on a phone, drag/cancel/resume, photo add/replace/delete, overlap and caption save/reload. No browser functional tests or screenshots were run.
