# 근처 수집가 레이더

## 사용하는 방법

1. 상단 로그인에서 구글 또는 카카오로 로그인합니다. 현재 방문자/로컬 관리자 키만으로는 위치 공유를 켤 수 없습니다.
2. 상단 지도 모양 아이콘을 누르고 안내를 읽은 뒤 이번 15분의 위치·대략적 거리·방향 공유에 동의합니다. 켜기 버튼을 누를 때만 브라우저 위치 권한을 요청합니다. 훔쳐보기에서도 오른쪽 위 아이콘으로 설정을 열 수 있습니다.
3. 앱 화면이 보이는 동안 30초마다 위치를 확인합니다. 서로 공유 중인 다른 계정이 약 1km 안에 있으면 앱 안 알림과 설정창 상태로 알려줍니다. 지도 없이 나를 중심으로 약 300m·600m·1km 원과 북쪽 기준 8방향에 익명 아이콘을 표시합니다. 같은 거리·방향의 여러 사람은 인원수로 묶습니다. 아이콘/목록을 선택하면 거리 구간과 방향을 읽을 수 있습니다. 상대 이름·사진·좌표·정확한 거리·방위각·고유 ID는 표시하지 않습니다.
4. 위치 아이콘 → 위치 공유 끄기로 중단합니다. 다른 앱/탭 전환, 로그아웃, 계정/서버 변경, 연결/권한 오류 및 15분 종료에도 중단합니다. 앱 안에서 홈·다이어리 등 페이지를 바꾸는 것은 공유를 유지합니다. 레이더 화면의 뒤로 가기는 공유 끄기와 다릅니다. 공유 중에는 상단 위치 아이콘이 활성 상태를 표시합니다.

공유는 새로고침/재진입 후 자동으로 켜지지 않습니다. 앱이 닫혀 있거나 숨겨진 동안의 푸시/소리/백그라운드 GPS는 이번 범위에 포함하지 않습니다. 브라우저 위치 권한과 실제 GPS 정확도는 기기·환경에 따라 다릅니다. 웹에서 받은 좌표가 실제 GPS인지 서버가 보증할 수는 없습니다.

화면 위쪽은 항상 북쪽이며 휴대폰의 방향을 나타내지 않습니다. 별도의 지도 SDK, Google Maps 키, 지오코딩·경로 API를 사용하지 않습니다. 기존 브라우저 Geolocation 좌표로 서버에서 근사 거리와 방위를 계산합니다. 지도가 아니므로 원 사이 간격은 실제 축척이 아닌 거리 구간 표현입니다.

방향은 두 기기의 측정 오차와 좌표 반올림을 고려해 `거리 <= max(150m, hypot(양쪽 accuracy)+140m)`이면 감춥니다. 실제 측정 오차를 보증하는 신뢰구간이 아닌 보수적인 표시 기준입니다. 이 경우 차트에 임의의 방향을 배치하지 않고 별도 거리 칩/목록으로 표시합니다. 같은 위치에서도 임의 북쪽 화살표가 생기지 않습니다.

## 개인정보와 수명

- 클라이언트에서 위·경도를 소수점 3자리(위도 기준 약 110m)로 줄인 후 인증된 API에 전송하고 서버도 다시 반올림합니다. 위치 오차가 250m를 넘거나 30초보다 오래된 측정은 공유를 중단합니다. 약 1km 판정은 근사값이며 경계에서 오차가 있습니다.
- 위치는 서버 프로세스 메모리의 최신 값 한 개만 유지합니다. DB·파일·브라우저 저장소·이동 이력·AI/크롤러 입력으로 쓰지 않습니다. 응답과 검증 오류에 좌표를 포함하지 않고 응답 캐시도 금지합니다.
- 로그인 인증이 확인된 요청에서만 사용자/세션을 정하며 요청 본문의 사용자 ID는 받지 않습니다. 공유별 임의 토큰을 로그인 세션에 묶습니다. 기존 존재 여부 동의만 보낸 클라이언트는 시작을 거부하고 새 거리·방향 안내를 요구합니다. 다른 계정·세션·이전 탭의 토큰으로 조회/갱신/종료할 수 없습니다.
- 공유 끄기/로그아웃 요청이 도착하면 즉시 제거합니다. 종료 요청이 네트워크 오류로 도착하지 않으면 마지막 갱신 후 90초부터 검색 대상에서 제외됩니다. 메모리 정리는 15초마다 실행하므로 만료된 위치 객체의 물리적 제거는 마지막 갱신 후 최대 약 105초가 걸릴 수 있습니다. 서버 종료/재시작 시 모든 공유가 사라집니다.
- 공유는 최대 15분입니다. 알림 간격 10분은 공유를 껐다 켜도 유지합니다. 이는 특정인과의 만남 이력이 아니라 사용자별 마지막 알림 시각만 임시 보관하는 제한입니다. 시작 요청 간격 10초, 위치 갱신 최소 20초, 요청 1KB, 최대 2,048명의 임시 사용자 제한을 둡니다. 제한용 사용자 식별자/시각은 최대 15분 후 제거합니다.

## 운영과 남은 확인

`server/nearby.py`의 메모리 저장소를 사용하므로 DB 마이그레이션은 없습니다. 현재처럼 API 프로세스 1개로 실행해야 합니다. 여러 worker/서버로 확장할 때는 짧은 TTL이 있는 별도 공유 저장소와 동일한 인증·보존 정책을 설계해야 합니다. 서버 다운 중에는 감지할 수 없습니다.

레이더 확장 후 근처 기능 31개 검증은 실제 기기 대신 합성 좌표를 사용합니다. 북쪽 기준 8방향, 거리 구간, 같은 위치/오차 큰 위치의 방향 숨김, 그룹 집계, 추적 식별자 미반환, 새 공유 동의와 중지·만료 후 집계 제거를 포함합니다. 로그인 제한, 명시적 동의, 상호 공유, 거리/날짜변경선, 잘못된 좌표·NaN·오차·과대 요청, 익명 응답, 계정/세션 분리, 종료 후 늦은 갱신 거부, 90초/15분 만료, 중복 알림, 메모리 한도 등을 검사합니다. 기존 소셜 로그아웃 검사에는 위치 공유 즉시 제거 확인도 추가했습니다. Flutter 웹 빌드·정적 타입과 JavaScript 문법을 확인했으며 실제 GPS나 화면 캡처 테스트는 하지 않았습니다.

사용자 확인: 구글·카카오 키 등록 후 **서로 다른 계정**으로 두 기기에서 로그인 → 가까운 위치에서 각각 공유 켜기 → 알림 확인 → 한 기기 끄기/탭 전환 → 다른 기기에서 다음 갱신 이후 사라지는지 확인합니다. 같은 계정의 여러 탭은 한 사람으로 취급하며 가장 최근에 켠 공유만 유지합니다. 권한 거부, 위치 오차가 큰 실내 환경, 인터넷 단절, 15분 만료도 확인 대상으로 남깁니다. 실제 좌표나 회원 토큰을 Git/보고서에 기록하지 않습니다.

브라우저 동작 근거: [W3C Geolocation](https://www.w3.org/TR/geolocation/), [MDN Geolocation](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation_API).


## 응답과 운영 경계

`POST /api/nearby/start`는 `consent: true`와 `radar: true`를 모두 요구합니다. update는 기존 nearby/notify/remaining_seconds에 count와 clusters를 추가합니다. 그룹은 `band: 0..2`, `direction: 0..7 또는 null`, `count`만 포함하며 사용자별 노드를 반환하지 않습니다. 3개 거리 × (8방향+불확실)로 최대 27그룹입니다. 동의하지 않거나 프로필 설정 전인 사용자를 임의로 표시하지 않으며 실제 사용자가 없을 때 예시 인물을 섞지 않습니다.

거리·방향이 거칠어도 위치 관련 정보입니다. 반복 관찰·여러 계정·위치 위조에 따른 추정 위험을 제거했다고 주장하지 않습니다. 위치정보법 적용 및 공개 운영 요건은 `LEGAL_REVIEW.md`의 검토 대상으로 유지합니다. 실기기·화면 검증은 사용자가 진행하도록 요청하여 자동 브라우저 캡처는 하지 않았습니다.
